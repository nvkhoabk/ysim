## 1. Purpose

This standard defines development, acceptance, sandbox and production boundaries for Release 1. It replaces stale proposed port/path values with a contract: actual values are accepted only after read-only discovery and collision review.

## 4. Mandatory sandbox/production isolation

Even when sharing a physical host, sandbox and production must have separate:

- release/application directories and immutable release identifiers;

- service names, environment files, working directories and process users where practical;

- databases and least-privilege database users;

- Redis instance/database/namespace and access control;

- queue names, locks, cron/timer identities and dead-letter paths;

- secret directories/files and provider credentials;

- webhook URLs, callback secrets and provider environments;

- mutable storage/uploads;

- logs, evidence, retention and alerts;

- backups and restore targets;

- email mode and recipient policy.

No shared database schema, credential file, webhook secret, mutable upload path, queue name, deployment working tree or customer-email allowlist is permitted.

## 7. Secret standard

- Secrets never enter Git, ZIP payload, documentation, screenshots or evidence.

- Files are owned by the runtime identity with minimum readable permissions.

- Public verification keys are stored separately from private credentials.

- Rotation is environment-specific and does not require source changes.

- YSim Payment Owner provider credentials are held only in the YSim environment secret boundary and are never copied into agency configuration.

- Provider tokens, webhook secrets and email tokens are never reused between sandbox and production.

- Diagnostics may print presence, readable/not-readable, owner/mode and fingerprint where safe; never the value.

## 8. Nginx and routing requirements

Before a routing mutation, collect redacted evidence for:

- nginx -T relevant server blocks;

- enabled/available site links;

- certificate paths and SNI names;

- upstream address/port;

- headers, timeouts and request-size limits;

- webhook path routing and body preservation;

- X-Forwarded-*, host and scheme behavior;

- noindex policy for sandbox;

- public health route and protected internal/operator routes.

- HTTP-to-HTTPS redirect for every public sandbox and production domain.

No new server block may reuse an existing server_name, upstream port or certificate identity without explicit review. Internal operator APIs must not become public merely because the web surface is public.

Sandbox and production support HTTPS only. Port 80 may exist solely to redirect the same host/path to HTTPS; business requests must never execute over HTTP.

## 9. Database, Redis and migration gates

- Migration runs against the named environment only.

- Pre-migration backup and restore target are recorded.

- Schema version is checked before and after.

- Redis keys/queues include an environment-safe boundary.

- Worker/scheduler remains OFF during migration unless the migration procedure explicitly requires otherwise.

- A failed migration stops activation and invokes the declared rollback/restore decision.

## 10. Provider environment contract

### GPay

- Sandbox and production endpoints/credentials/webhooks are independent.

- One shared GPay webhook URL may route several contracted services; internal routing must remain authenticated and idempotent.

- Browser return is not authoritative.

- GPay is not an agency credit top-up channel in R1. When an agency authorizes YSim as Payment Owner for an end-customer transaction, the YSim provider credential boundary and transaction attribution must be explicit.

### OnePay

- Sandbox and production endpoints/credentials/callbacks are independently gated.

- OnePay is not an agency credit top-up channel in R1.

- Optional Agency Payment Owner use is disabled until OnePay's own hosted-flow, IPN, QueryDR, reconciliation and production gates pass.

### Gigago

- Sandbox evidence: getMyOrdersAgency accepts POST and rejects PUT with 405.

- Production method is independently probed/confirmed and configured with GIGAGO_GET_MY_ORDERS_METHOD or its canonical equivalent.

- No production purchase is allowed during connectivity-only checks.

### Email

- Modes: disabled, dry-run and live/allowed delivery as implemented.

- Live customer delivery requires a separate approval and audit trail.

### Authorized sandbox transactions

- Bounded GPay and OnePay sandbox transactions and Gigago sandbox orders are approved for commissioning evidence.

- Each run records provider environment, correlation/reference, bounded count, outcome and reconciliation without exposing secrets or full eSIM data.

- Authorization does not extend to production endpoints, production purchases or non-allowlisted recipients.

## 12. YSim-Debian12 WSL / Windows browser contract

- Windows browser executables launched from WSL are cross-OS processes.

- Do not assume loopback equivalence.

- Use the validated command-line screenshot/DOM path or a separately proven host transport.

- Write Windows browser output to a Windows-writable temporary path before importing it into WSL evidence.

- Capture exit code, timeout and redacted stderr.

- Probe browser transport before source/runtime mutation; browser transport never changes the canonical WSL source-execution boundary.

- Order and financial records follow the approved accounting/legal retention policy.
