# UXF-03 — Storefront Template & Page Composition

---

# 1. Purpose

This document defines the Storefront Runtime Model of the YSim Platform.

Unlike traditional websites composed from static pages, YSim storefronts are generated dynamically from reusable templates, page definitions, business components and runtime context.

This document defines:

- Storefront Templates
- Layout Engine
- Page Composition
- Section Engine
- Component Registry
- Business Widgets
- Runtime Rendering
- CMS-lite Architecture

---

# 2. Storefront Philosophy

A Storefront is **NOT** a website.

A Storefront is a commercial experience generated by the platform.

```
Runtime Context

↓

Storefront Profile

↓

Template

↓

Layout

↓

Sections

↓

Components

↓

Business Data

↓

Rendered Experience
```

The storefront itself contains almost no business logic.

---

# 3. Storefront Model

Every storefront consists of:

```
Storefront

├── Experience Profile

├── Template

├── Layout

├── Business Bindings

├── Navigation

├── Assets

├── Localization

├── Runtime Policies

└── Published Snapshot
```

---

# 4. Template Engine

A Template defines the overall page structure.

Templates never contain business data.

A Template specifies:

- Layout
- Regions
- Section Slots
- Component Slots
- Responsive Rules

---

# 5. Built-in Templates

The platform initially provides three templates.

## Travel Landing

Optimized for inbound travelers.

Typical layout:

```
Hero

↓

Destination Selector

↓

Popular Packages

↓

Coverage

↓

How It Works

↓

FAQ

↓

Footer
```

---

## Catalog

Optimized for browsing many products.

```
Search

↓

Filters

↓

Product Grid

↓

Comparison

↓

Cart

↓

Checkout
```

---

## Campaign Landing

Optimized for marketing campaigns.

```
Hero Banner

↓

Promotion

↓

Featured Products

↓

Call To Action

↓

Testimonials

↓

FAQ

↓

Support
```

---

# 6. Layout Engine

Layouts define the physical structure of pages.

Supported layouts:

- Single Column
- Two Columns
- Three Columns
- Dashboard
- Split Layout
- Sidebar Layout
- Wizard Layout

Layouts are reusable across templates.

---

# 7. Page Composition

Pages are generated dynamically.

```
Page

↓

Regions

↓

Sections

↓

Components

↓

Business Data
```

Pages are configuration-driven.

---

# 8. Regions

Typical regions include:

- Header
- Hero
- Main Content
- Sidebar
- Promotion Area
- Footer
- Floating Actions

Regions provide containers for sections.

---

# 9. Section Engine

A Section groups related business components.

Examples:

Hero Section

Product Section

Promotion Section

Support Section

FAQ Section

Review Section

Payment Section

Every section can be enabled, disabled or reordered.

---

# 10. Component Registry

Every component belongs to the shared UI registry.

Examples:

Generic Components

- Button
- Card
- Modal
- Table
- Form
- Badge

Business Components

- Destination Selector
- Country Card
- Package Card
- Coverage Map
- Package Comparison
- Promotion Banner
- Cart Summary
- Checkout Progress
- QR Delivery Card
- Activation Timeline
- Support Widget
- Order Status
- eSIM Detail Card

No storefront implements custom versions of these components.

---

# 11. Business Widgets

Business Widgets connect UI with platform capabilities.

Examples:

```
Featured Products Widget

↓

Catalog Binding

↓

Pricing Binding

↓

Promotion Binding

↓

Rendering
```

Another example:

```
Destination Selector

↓

Country Catalog

↓

Runtime Availability

↓

Rendering
```

Widgets never query suppliers directly.

---

# 12. Component Binding

Components bind only to platform capabilities.

```
Component

↓

Capability

↓

Application Service

↓

Business Object
```

Components never depend on:

- Supplier
- Database
- External APIs

---

# 13. Storefront Profile

A Storefront Profile defines page behavior.

Example:

```
Storefront Profile

├── Homepage Layout

├── Hero Configuration

├── Featured Catalog

├── Navigation

├── Search Configuration

├── Footer

├── CTA

├── Support

└── Empty State
```

Storefront Profiles extend Experience Profiles.

---

# 14. Page Configuration

Every page is configuration driven.

Example:

```
Home

├── Hero

├── Search

├── Featured Products

├── Coverage

├── Reviews

├── FAQ
```

Each section may be independently configured.

---

# 15. CMS-lite

YSim provides lightweight page composition.

Supported operations:

- Enable Section
- Disable Section
- Reorder Section
- Replace Component
- Configure Component
- Configure Widget

Drag-and-drop editing is not required for MVP.

---

# 16. Runtime Rendering

Storefront rendering pipeline:

```
Request

↓

Experience Context

↓

Storefront Profile

↓

Template

↓

Layout

↓

Sections

↓

Widgets

↓

Business Data

↓

Rendered Page
```

---

# 17. Navigation Composition

Navigation is generated from runtime configuration.

Sources include:

- Experience Profile
- Storefront Profile
- Localization
- Feature Flags
- Runtime Policies

Navigation is never hardcoded.

---

# 18. Responsive Rendering

Responsive rendering affects:

- Layout
- Navigation
- Hero
- Card Size
- Grid
- CTA Placement

Business behavior remains identical.

---

# 19. Experience Preview

Every Storefront supports Preview Mode.

```
Draft

↓

Preview

↓

Publish
```

Preview renders using unpublished configuration without affecting production.

---

# 20. Storefront Snapshot

Published storefronts generate immutable snapshots.

Snapshots include:

- Template
- Layout
- Sections
- Widgets
- Assets
- Navigation
- Runtime Policies

Runtime renders snapshots rather than editable configuration.

---

# 21. AI Implementation Guidelines

AI agents shall:

- Never hardcode pages.
- Never hardcode layouts.
- Never hardcode navigation.
- Never hardcode widgets.
- Use reusable templates.
- Use configuration-driven composition.
- Separate business widgets from presentation.
- Resolve business data through platform services only.
- Never access suppliers directly.

---
